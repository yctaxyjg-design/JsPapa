# FT Edit 분석 크로스체킹

## 대상 파일 찾기

1. `$ARGUMENTS`에 경로가 있으면 그것을 쓴다.
2. 없으면 이번 세션 첨부파일을 확인한다.
3. 그래도 없으면 업로드 폴더를 탐색한다:
   `ls -t /root/.claude/uploads/*/ 2>/dev/null | grep -i ftedit`
4. 끝내 못 찾으면 **추측하지 말고** 사용자에게 파일을 올려달라고 요청하고 중단한다.

## 절차

`ftedit/PROTOCOL.md`를 읽고 그대로 따른다. 요약하면:

1. 분석 문서에서 검증 가능한 주장을 추출 (수치 → 인과·귀속 → 구조 → 최상급 → 반사실 순)
2. `ftedit/PROTOCOL.md`의 **알려진 반복 오류 패턴(P1~P6)부터** 훑는다
3. 기사당 1~2회 `WebSearch`로 외부 대조. 수치 밀도 높은 기사 우선, 통상 6건이면 충분
4. Tier 1(사실오류) / Tier 2(분석적 누락) / Tier 3(잘한 점)로 분류
5. 고정 5축으로 품질 채점 — 사실 정확도, 증거 등급 구분, 논증 구조, 반증 규율, 프레임워크 절제
6. 반복될 구조적 패턴 진단 + 다음 회차 프롬프트 개선 제안
7. `ftedit/crosscheck/YYYY-MM-DD.md`에 저장, 출처 URL 첨부, 커밋

## 반드시 지킬 것

- FT 원문은 유료화로 접근 불가 → **"분석의 오류인지 FT 원문의 오류인지 구분되지 않는다"**는 한계를 문서 첫머리에 명시
- 기업 계약·금융 수치는 **PR Newswire 원문 보도자료**가 가장 정확. 언론 요약 헤드라인은 조건부 최대치를 확정액으로 뽑는 경향이 있으니 주의
- Tier 3(잘한 점)을 생략하지 않는다
- 검증 못 한 항목은 검증 못 했다고 쓴다
- 직전 회차 `ftedit/crosscheck/` 파일을 읽고 **패턴 재발 여부**를 언급한다
