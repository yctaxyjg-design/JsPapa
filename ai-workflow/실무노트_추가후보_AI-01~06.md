## AI-01 `추론` AI 멀티워크플로 표준 — 3층 구조

에이전트별 설정을 복제하지 말고 한 곳에서 관리해 배포한다. 층을 섞지 않는 게 핵심이다.

| 층 | 원칙 | 수단 |
|---|---|---|
| 구성 | Single Source | Agent Import / Sync (Codex `/import` 등) |
| 병렬 판단 | Shared-Prefix Cache | Claude Code fork + fan-out |
| 반복·검증가능 처리 | Local-first | Ollama MLX 등 로컬 모델 |
| ambient memory | allowlist only | include-only, 예측 불가 앱은 제외 |

멀티에이전트의 실질 병목은 모델 성능이 아니라 **구성 드리프트**(같은 규칙을 도구별로 따로 관리)라는 게 이 표준의 전제다.

## AI-02 `추론` 병렬화는 그 자체로 싸지지 않는다

prompt cache 공유는 **입력 prefix** 비용만 줄인다. agent 수가 늘면 출력·도구호출 비용은 그대로 늘어난다.

- 이득: shared prefix가 큰 조사·리뷰·다중 관점 분석
- 손해: 짧은 작업 — 단일 agent가 싸다

"fork 썼으니 저렴하다"로 넘어가지 말고 총 토큰·cache-read·시간·품질 4종을 실측해서 판단할 것.

## AI-03 `추론` 설정 import는 권한 이관이다 — deny부터 확인

한 에이전트의 설정을 다른 에이전트로 변환할 때, **allow는 잘 넘어가고 deny는 조용히 사라질 수 있다.** deny가 유실되면 결과적으로 권한이 넓어진 상태가 된다.

import 후 diff에서 이 순서로 본다.

1. deny 목록이 살아있는가
2. 파괴적 명령(`rm`, `mv`, `chmod`)이 **어떤 범위로** 매핑됐는가
3. MCP 인증·환경변수·hooks·shell interpolation이 그대로 실행 가능한 상태인가

첫 import는 반드시 **자동 동기화를 끄고** 한다. 자동 sync는 diff가 깨끗하다는 걸 확인한 뒤에 켠다.

## AI-04 `확인` 이 저장소의 import 대상 인벤토리

`.claude/` 실측 (2026-08-17 기준).

| 자산 | 개수 |
|---|---|
| slash commands (`.claude/commands/`) | 2 — `economist-weekly`, `ftedit-crosscheck` |
| skills (`.claude/skills/`) | 1 — `frontend-polish` |
| permissions (`.claude/settings.json`) | allow 26 / deny 2 |
| hooks | 없음 |
| 프로젝트 스코프 MCP (`.mcp.json`) | 없음 |
| `CLAUDE.md` | 없음 |

hooks와 프로젝트 MCP가 없어서 import 첫 시험의 사고 반경이 작다. 반대로 **`CLAUDE.md`가 없다**는 건 프로젝트 메모리가 이관될 게 없다는 뜻이기도 하다 — import 이득을 제대로 재려면 CLAUDE.md를 먼저 만들어두는 편이 낫다.

`settings.json` allow에 `Bash(rm:-f *)`, `Bash(mv:*)`, `Bash(chmod:*)`가 있다. AI-03의 2번 항목이 이 저장소에 그대로 걸린다.

## AI-05 `추론` 로컬 모델의 "로컬성"은 harness가 정한다

로컬 추론만 쓰면 API 토큰 비용은 0이고 원문도 기기 밖으로 나가지 않는다. 그러나 **agent harness가 web/MCP/cloud tool을 호출하도록 열어두면 그 부분은 로컬이 아니다.**

로컬성을 근거로 민감자료를 태우기 전에 tool 접근을 끄고 측정할 것. 모델을 로컬로 바꾼 것과 파이프라인을 로컬로 만든 것은 다른 얘기다.

## AI-06 `미검증` 속도 개선 수치는 측정 대상 모델에 붙어 있다

Ollama 0.32.10의 prefill 약 78% 개선은 **일부 NVFP4 MLX 모델(Qwen3.6·Muse Glimmer) 대상 측정치**다. 같은 런타임을 쓴다고 해서 Qwen3.8에 그대로 옮겨 붙일 수 없다.

일반화하자면 — 런타임 릴리스 노트의 성능 수치는 항상 **어느 모델·어느 양자화에서 잰 것인지**를 같이 읽는다. 그 조건이 안 적혀 있으면 인용하지 않는다.
