## 1. Codex가 Claude·Cursor 설정을 그대로 받는다 — 97%

**주장** `제공`

- 8/11부터 ChatGPT 데스크톱이 Claude Code·Claude Cowork·Cursor의 instructions / settings / skills / plugins / projects / 최근 작업을 가져올 수 있다. 이후 변경사항 자동 동기화도 가능
- Codex CLI는 `/import`로 Claude Code·Cursor를 가져온다
- 변환 대상에 MCP 설정·hooks·slash commands·subagents·Claude project memories가 포함된다
- 기존 Claude/Cursor 쪽 설정은 **변경·삭제하지 않는다**
- OpenAI도 가져온 MCP 인증·환경변수·hooks·shell interpolation·tool permission은 **다시 검토하라고 명시**한다

**왜 큰가** `추론`

지금까지 멀티에이전트의 실질 병목은 모델 성능이 아니라 "Claude용 규칙 / Codex용 규칙 / Cursor용 규칙을 따로 관리한다"는 구성 드리프트였다. 프로젝트 설명·규칙·MCP 환경을 매번 다시 설명하는 입력 토큰과 초기 세팅 시간이 줄어들 가능성이 높다. 모델 단가가 내려가는 건 아니다.

**이 저장소가 import될 때 실제로 넘어가는 것** `저장소확인`

| 자산 | 경로 | 개수·내용 |
|---|---|---|
| slash commands | `.claude/commands/` | 2개 — `economist-weekly`, `ftedit-crosscheck` |
| skills | `.claude/skills/` | 1개 — `frontend-polish` (SKILL.md 단일 파일) |
| permissions | `.claude/settings.json` | allow 26 / deny 2 |
| hooks | — | **없음** |
| MCP (프로젝트 스코프) | `.mcp.json` | **없음** (MCP는 전부 사용자 스코프에 있음) |
| CLAUDE.md | — | **없음** (루트에 프로젝트 메모리 파일이 없다) |

즉 이 저장소는 import 시험용으로 **딱 적당하다.** 넘어갈 게 있으면서(commands 2 + skill 1 + permissions 28줄) hooks·프로젝트 MCP가 없어서 첫 시험에서 사고 반경이 작다. 별도의 작은 repo를 새로 만들 필요 없이 여기서 시험하면 된다.

주의할 지점 두 개:

1. `settings.json`의 allow 목록에 `Bash(rm:-f *)`, `Bash(chmod:*)`, `Bash(mv:*)` 가 있다. Codex 쪽 권한 모델로 변환됐을 때 **이 셋이 어떤 범위로 매핑되는지**를 diff에서 제일 먼저 볼 것
2. `deny` 2건(`WebFetch(domain:click.e.economist.com)`, `Bash(curl:*click.e.economist.com*)`)이 **변환 후에도 살아남는지** 확인. deny가 조용히 사라지면 allow만 넘어간 것이고, 그건 권한이 넓어진 상태다

**시험 절차**

- [ ] 자동 동기화 **끄고** 시작
- [ ] 이 저장소 하나만 import
- [ ] 변환 결과 diff — `AGENTS.md`, `config.toml`, skills, MCP
- [ ] allow/deny 매핑 확인 (위 주의 1·2)
- [ ] 동일 작업 1건을 Claude와 Codex 양쪽에서 실행해 결과 비교
- [ ] 통과하면 자동 sync ON

**합격 기준** 변환된 설정으로 Codex가 `frontend-polish` 규칙을 지키면서 같은 작업을 수행하고, deny 2건이 살아있을 것.
**중단 조건** deny가 유실되거나, `rm -f` 계열이 무제한 권한으로 매핑되면 즉시 중단하고 수동 작성으로 전환.

## 2. Claude Code가 "싸게 병렬화"하는 방향으로 움직였다 — 95%

**주장** `제공`

- 2.1.232 (8/13)부터 `subagent_type: "fork"`가 기본 활성화. fork된 agent가 현재 대화 전체와 prompt cache를 상속하고, 일반 subagent는 기본적으로 백그라운드 실행
- 2.1.229 (8/12)에서 fan-out 로직 변경 — 같은 prefix를 가진 sibling agents를 시간차로 시작해 뒤의 agent가 같은 prompt prefix를 다시 결제하지 않고 cache에서 읽는다
- 2.1.233에서 서버리스 MCP 서버가 장기 stream을 끊을 때 MCP v2가 재접속 루프를 도는 문제 수정
- 보안: nested git repo별 trust 확인, GitLab secret redaction, PowerShell·symlink 우회 차단

→ **2.1.233 이상에서 시험하는 게 맞다.**

**해석** `추론`

하나의 문제를 ①법리/코드 분석 ②반례 탐색 ③테스트 작성 세 agent에 동시에 맡길 때, 공통 프로젝트 설명과 긴 컨텍스트를 세 번 통째로 태우는 낭비가 줄어든다. 다만 **"병렬화 = 싸짐"은 아니다.** agent 수가 늘면 출력·도구호출 비용은 그대로 증가한다. shared prefix가 큰 조사·리뷰 작업일수록 이득이고, 짧은 작업은 단일 agent가 싸다.

**A/B 설계** — 같은 중간급 작업 1건을 두 번 돌린다.

| | A | B |
|---|---|---|
| 구성 | 단일 agent 직렬 | fork 3개 + 최종 synthesis |
| 측정 | 총 토큰 / cache-read 토큰 / 완료시간 / 결과품질 | 동일 |

**시험 대상 작업 후보** (이 저장소 안에서 shared prefix가 큰 것)

- `scripts/tax/reconcile_local_income_tax.py` 리뷰 — 실무노트 E-42의 ±2,500 대 ±2,000 충돌 확인 포함 (`scripts/tax/실무노트_추가후보_E-42~52.md` 참조). 컨텍스트가 크고 세 갈래(코드 정합 / 실무노트 대조 / 반례 케이스)로 자연스럽게 쪼개진다
- `math-play` + `hangul` + `flag-color` 3개 앱의 접근성 동시 점검 — prefix(= frontend-polish 규칙)가 공유되고 대상만 다르다

- [ ] 2.1.233 이상 확인
- [ ] A 실행, 지표 4종 기록
- [ ] B 실행, 지표 4종 기록
- [ ] 비용 비슷 + 품질/시간 개선이면 fork를 표준 패턴으로 채택

**합격 기준** 총 비용이 A 대비 +20% 이내이면서 완료시간 또는 품질이 뚜렷이 개선.
**주의** agent 수가 늘면 권한면(permission surface)도 같이 늘어난다. `settings.json` allow에 있는 `rm`/`mv`/`chmod`를 fork 3개가 동시에 쓸 수 있는 상태라는 뜻이다.

## 3. 로컬 Mac — Qwen3.8 27B MLX — 92%

**주장** `제공`

- Ollama 0.32.12 (8/14)가 Qwen3.8 27B 추가, Apple Silicon용 `qwen3.8:27b-mlx` 제공
- MLX 모델 약 18GB, vision/tools/thinking 지원. 0.32.13에서 developer instructions 지원 추가
- 0.32.10부터 일부 NVFP4 MLX 모델의 prefill이 공식 측정상 약 78% 개선, speculative decoding 기본값 개선
- MLX 본체는 0.32.0 (7/7)이 최신 — 이번 주 별도 업데이트 실험 없음

```
ollama run qwen3.8:27b-mlx
```

**주의 — 78%를 Qwen3.8에 붙이지 말 것.** 그 수치는 Qwen3.6·Muse Glimmer 대상 측정이다. Qwen3.8이 78% 빨라졌다는 뜻이 아니다.

**메모리** `추론` 18GB가 모델 자체 크기이므로 통합메모리 32GB 이상에서 편하게 돈다. 24GB도 구동 가능성은 있지만 긴 context의 KV cache와 다른 앱까지 감안하면 빠듯하다.

**시험 방식** — 공식 벤치마크 숫자를 믿을 필요가 없다. **정답을 나중에 검증할 수 있는 작업 3개**를 직접 돌려 클라우드 저가 모델과 비교한다.

- [ ] 자료 분류 — 정답 라벨을 사람이 확인 가능한 것
- [ ] JSON 추출 — 스키마 검증으로 자동 채점 가능
- [ ] 긴 문서 전처리 / 코드 초벌 — 후속 단계에서 오류가 드러남

**경계** 로컬 추론만 쓰면 API 토큰 비용은 0이고 원문도 Mac 밖으로 나가지 않는다. 다만 agent harness가 web/MCP/cloud tool을 호출하도록 열어두면 **그 부분은 로컬이 아니다.** 로컬성을 주장하려면 tool 접근을 끄고 측정해야 한다.

## 5. Computer History — 개인 Mac 한정 — 70%

**주장** `제공`

- 8/13 macOS ChatGPT에 추가. 선택한 앱·웹사이트에서 사용자 활동을 모아 ChatGPT/Codex가 쓸 timeline과 memory로 만든다
- 스크린샷·화면녹화·마이크·시스템 오디오는 기록하지 않는다. 기능 자체가 기본 OFF
- 이벤트는 Mac에 최대 48시간 잔존
- 생성된 memory는 `~/.codex/memories/extensions/skysight/` 아래 **암호화되지 않은 plain-text Markdown**으로, 삭제할 때까지 남는다
- 이벤트를 memory로 요약할 때 OpenAI 서버에서도 처리된다
- 공식 문서가 웹페이지·앱 콘텐츠를 통한 **prompt injection 위험 증가**를 명시한다

**판단** `추론` **업무용 전체 활성화는 반대.** plain-text 영구 잔존 + 서버 요약 처리 + injection 표면 증가 + 주기적 요약의 토큰 비용까지 겹친다.

시험한다면 **include-only(allowlist)** 로:

- [ ] 포함: VS Code + 비민감 로컬 노트 정도만
- [ ] 제외: 브라우저 전체, 메일, 개인정보·행정 시스템 등 **내용 범위를 예측할 수 없는 앱**
- [ ] 일주일 사용 후 판정 기준 하나만 본다 — "내가 하던 일을 다시 설명하지 않아도 이어주는가"
- [ ] 입증되면 그때 범위를 조금씩 확대
